# Баги и решения — CTRL home

Памятка по проблемам, на которые мы уже наступили, и как их чинить/не повторять.
Обновлено: 26 июня 2026.

**Шпаргалка по проекту**
- Репозиторий: `alexpanfilova1-debug/ctrl-home-website` (ветка `main`, **публичный**)
- Сайт онлайн: https://alexpanfilova1-debug.github.io/ctrl-home-website/
- Хостинг: GitHub Pages (Source: *Deploy from a branch* → `main` / `/root`)
- Деплой: любой **push в `main`** автоматически пересобирает сайт (~1–2 мин)

## ✅ Правильный процесс обновления сайта (делать так — и проблем не будет)

1. Внести правки в файлы (сам(а) или вместе с Claude — Claude меняет файлы инструментом редактирования).
2. В **GitHub Desktop**: вписать Summary → **Commit to main** → **Push origin**.
3. Подождать 1–2 минуты — GitHub Pages пересоберёт сайт.
4. Открыть боевой адрес и нажать **Cmd+Shift+R** (жёсткая перезагрузка, чтобы не показывалась старая версия из кэша).

> Золотое правило: **коммит и push делаю я (через GitHub Desktop), а не Claude через песочницу.** Это избавляет от ошибки с lock-файлом (см. баг №4).

## 🐞 Решённые проблемы

### 1. Не включается GitHub Pages — «Upgrade or make this repository public»
- **Симптом:** в *Settings → Pages* вместо настроек висит надпись «Upgrade or make this repository public to enable Pages», блока *Build and deployment* нет.
- **Причина:** репозиторий приватный, а бесплатный GitHub Pages работает только с **публичными** репозиториями.
- **Решение:** *Settings → General →* прокрутить вниз до *Danger Zone →* **Change repository visibility → Make public →** подтвердить (ввести имя репозитория).
- **Как не повторить:** для бесплатного хостинга держим репозиторий публичным. В нём только код сайта, фото и тексты — секретов нет. Пароли/ключи (ЮKassa, доступы) в репозиторий не коммитим НИКОГДА.

### 2. Кнопка «Save» в настройках Pages серая / «не нажимается»
- **Симптом:** ветка выбрана, а кнопка Save серая и не нажимается.
- **Причина:** это **не баг**. Save серая, когда сохранять нечего — настройка уже применена (`main` / `/root` уже выбраны и сохранены ранее).
- **Решение:** ничего не жать. Закрыть выпадающий список (крестик ✕), оставив выбранной `main`. Обновить страницу — вверху появится статус сайта.
- **Как не повторить:** серая Save = «уже сохранено», это нормальное состояние.

### 3. Сайт открывается как «Site not found» (ошибка 404)
- **Симптом:** по адресу `…github.io/ctrl-home-website/` — страница «Site not found».
- **Причина:** (а) первые 1–2 минуты после включения Pages это нормально — идёт первая сборка; (б) у нас первая сборка вообще не стартанула от одного лишь включения Pages (журнал `Actions` был пуст).
- **Решение:** сделать любой коммит и **push в `main`** — именно push запускает сборку Pages. Через 1–2 минуты сайт поднимается. Старую 404 в браузере убрать жёсткой перезагрузкой **Cmd+Shift+R**.
- **Как не повторить:** сразу после включения Pages сделать один push в `main`, чтобы гарантированно запустить первую сборку. Видишь 404 дольше пары минут — не ждать, а «толкнуть» коммитом.

### 4. GitHub Desktop: «A lock file already exists in the repository»
- **Симптом:** при Commit/Push в GitHub Desktop — ошибка про lock-файл, операция не проходит.
- **Причина:** в служебной папке `.git/` остались «зависшие» файлы `index.lock` / `HEAD.lock`. Они появляются, когда git-команды запускаются в папке проекта **из песочницы Claude** — оттуда git не может сам удалить свой lock после операции.
- **Решение:** открыть **Терминал** и выполнить (удаляет застрявшие технические файлы, безопасно):
  ```
  rm -f "$HOME/Claude/Projects/собираем сайт/.git/"*.lock
  ```
  затем повторить Commit + Push в GitHub Desktop.
- **Как не повторить:** **не запускать git-команды в этой папке через Claude.** Claude правит файлы, а `commit` и `push` делаешь ты в GitHub Desktop.
